## 0. ARCHITECTURE PRINCIPLE (Corrected & Honest)

**Adansi is a software layer. It is NOT a bank. It does NOT hold deposits.**

For accumulation savings (funeral funds, wedding funds, business pools), **money MUST be pooled.** There is no architectural trick that avoids this. Amina pays Monday, Kofi pays Wednesday, Yaw pays Friday — that money must sit somewhere while waiting for the full target.

**The only honest architecture:**
- **MVP (Hackathon):** Pooled funds sit in Adansi's Hubtel merchant settlement account. Adansi's PostgreSQL database tracks which group owns what portion.
- **Phase 2:** Partner with a licensed rural bank. Each group opens a real savings account. Adansi provides only the software layer.
- **Phase 3 (Vision):** MTN provides group-level MoMo wallets or sub-merchant accounts through deep API partnership.

**This is how every Ghanaian fintech started.** SusuCollect, Chipper Cash, Cowrywise — all began with merchant settlement accounts before securing banking partnerships.

## 1. THE FUND CUSTODY PROBLEM — ANSWERED DIRECTLY

### 1.1 Where Is the Money? (Accumulation Groups)

```
Amina pays GHS 100 on Monday via MTN MoMo
    ↓
Hubtel deducts from Amina's wallet
    ↓
Hubtel settles GHS 98.50 into Adansi's merchant account (GHS 1.50 fee)
    ↓
Adansi DB records: "Funeral Fund balance += GHS 98.50"
    ↓
Kofi pays GHS 100 on Wednesday via Telecel
    ↓
Same flow. Adansi's merchant account now holds ~GHS 197.
    ↓
Adansi DB: "Funeral Fund balance = GHS 197"
    ↓
3 months later: 30 members × GHS 100 × 12 weeks = GHS 36,000
    ↓
Adansi's merchant account holds ~GHS 35,460 (after fees)
    ↓
Adansi DB tracks: "Funeral Fund balance = GHS 36,000"
    ↓
Treasurer requests GHS 8,000 for coffin
    ↓
2 of 3 treasurers approve digitally
    ↓
Hubtel disburses GHS 8,000 DIRECTLY to coffin maker's MoMo
    ↓
Adansi DB: "Funeral Fund balance = GHS 28,000"
```

**The money is physically in Hubtel's regulated merchant settlement infrastructure.**
**Adansi's database is the ledger tracking group ownership.**

### 1.2 Where Is the Money? (Rotating Savings / Susu)

```
Week 1: All 5 members must pay GHS 200
    ↓
Adansi triggers collection from each member's MoMo on Monday
    ↓
GHS 1,000 collected into Adansi's merchant account
    ↓
Immediately disbursed to Week 1 beneficiary (Yaw Addo)
    ↓
Adansi DB records: "Yaw received GHS 1,000. Next: Amina"
    ↓
Money does NOT sit. It flows through.
```

For rotating savings, money can flow through without pooling. For accumulation, it must pool.

## 2. IS ADANSI A BANK? NO.

### 2.1 Regulatory Reality

| Question | Answer |
|----------|--------|
| Is Adansi licensed by Bank of Ghana? | **No.** Not for the MVP. |
| Is this legal? | **Yes, for small-scale testing.** Every Ghanaian fintech starts here. |
| When does licensing become required? | When holding deposits at scale (GHS 500K+ or 1,000+ active groups). |
| What license is needed? | Payment Service Provider (PSP) or Deposit-Taking license. |
| How much capital? | PSP: ~GHS 2–5M. Deposit-taking: GHS 15–60M. |
| Can 3 students afford this? | **No.** This is why Phase 2 requires a bank partner. |

### 2.2 What Adansi Actually Is (Legally)

For the hackathon, Adansi is:
- A **software provider** of group treasury management tools
- A **merchant** using Hubtel's payment APIs to collect and disburse funds
- Funds are held "pending disbursement to beneficiaries"
- Adansi does not advertise interest, savings products, or deposit-taking

**This is the same legal position as SusuCollect, Cowrywise, and every fintech MVP in Ghana.**

## 5. CREDIT SCORE REQUIREMENT: ACTUAL TRANSACTIONS

You asked: *"How does the credit score work if people hold money in their own wallets?"*

**Answer: It doesn't.** That is why the on-demand collection idea was wrong.

The social credit score requires **proof that money actually left the member's wallet and entered the group pool.**

| Scenario | Credit Impact |
|----------|---------------|
| Amina pays GHS 100 into group pool on time | ✅ Score increases. Consistency + Volume tracked. |
| Amina promises to pay but keeps money in her wallet | ❌ No transaction. No score increase. |
| Amina pays 3 days late | ⚠️ Score increases slightly less. Late payment recorded. |
| Amina misses payment entirely | ❌ No score increase. Missed payment hurts score. |
| Amina is a treasurer who approves 10 withdrawals on time | ✅ Standing factor increases. |

**The score is built from ACTUAL on-ledger transactions, not promises.**

```sql
-- Users
CREATE TABLE users (

  year INT NOT NULL,
  month INT NOT NULL,
  total_contributions DECIMAL(12,2) DEFAULT 0,

  member_count INT DEFAULT 0,
  contribution_count INT DEFAULT 0,
  UNIQUE(group_id, year, month)

-- User Contribution History View
CREATE VIEW user_contribution_history AS
SELECT 
  c.user_id,
  c.group_id,
  g.name as group_name,
  c.amount,
  c.status,
  c.method,
  c.network,
  c.created_at,
  cs.status as schedule_status,
  CASE 
    WHEN cs.paid_at <= cs.expected_date THEN 'on_time'
    WHEN cs.paid_at > cs.expected_date THEN 'late'
    ELSE 'missed'
  END as timeliness
FROM contributions c
LEFT JOIN contribution_schedules cs ON cs.contribution_id = c.id
LEFT JOIN groups g ON g.id = c.group_id;
```

## 8. HUBTEL API INTEGRATION (Reference-Tagged Collections)

### 8.1 Contribution Collection

```python
# Backend: hubtel_client.py

import requests
import uuid

HUBTEL_BASE_URL = "https://api.hubtel.com/v1"
HUBTEL_CLIENT_ID = "your-client-id"
HUBTEL_CLIENT_SECRET = "your-client-secret"
HUBTEL_MERCHANT_ACCOUNT = "your-merchant-account-number"

def initiate_momo_collection(
    customer_phone: str,
    customer_network: str,  # 'mtn', 'telecel', 'airteltigo'
    amount: float,
    group_id: str,
    group_reference: str,
    description: str
) -> Dict:
    """
    Initiates MoMo collection from a group member.
    Uses group_reference to tag the payment for ledger attribution.
    """
    reference = f"AD-{group_reference}-{uuid.uuid4().hex[:8]}"

    payload = {
        "CustomerName": "Adansi Group Member",
        "CustomerMsisdn": customer_phone,
        "CustomerEmail": "",
        "WalletProvider": customer_network,
        "Amount": amount,
        "PrimaryCallbackUrl": "https://adansi.app/api/contributions/callback",
        "Description": description,
        "ClientReference": reference,
        "MerchantAccountNumber": HUBTEL_MERCHANT_ACCOUNT,
        "TransactionId": reference
    }

    response = requests.post(
        f"{HUBTEL_BASE_URL}/merchantaccount/merchants/{HUBTEL_CLIENT_ID}/receive/mobilemoney",
        json=payload,
        auth=(HUBTEL_CLIENT_ID, HUBTEL_CLIENT_SECRET)
    )

    return {
        "reference": reference,
        "status": response.json().get("Status"),
        "payment_url": response.json().get("PaymentUrl")
    }

def handle_collection_callback(webhook_data: Dict, db):
    """
    Hubtel sends webhook when payment completes.
    We use the ClientReference to attribute to the correct group.
    """
    reference = webhook_data["ClientReference"]
    status = webhook_data["Status"]
    amount = webhook_data["Amount"]

    # Extract group reference from ClientReference: "AD-FUN-1234-abc123"
    group_ref = reference.split("-")[1] if "-" in reference else None

    if status == "Success":
        group = db.get_group_by_reference(group_ref)
        if group:
            # Create contribution record
            db.create_contribution({
                "group_id": group["id"],
                "amount": amount,
                "hubtel_transaction_id": webhook_data["TransactionId"],
                "hubtel_reference": reference,
                "status": "completed"
            })

            # Update group balance
            db.increment_group_balance(group["id"], amount)

            # Update credit score for payer
            update_credit_score(webhook_data["CustomerMsisdn"])

            # Notify group members
            notify_members(group["id"], f"GHS {amount} contributed by {webhook_data['CustomerMsisdn']}")
```

### 8.2 Direct Beneficiary Disbursement

```python
def disburse_to_beneficiary(
    group_id: str,
    amount: float,
    beneficiary_phone: str,
    beneficiary_network: str,
    reason: str,
    withdrawal_id: str
) -> Dict:
    """
    Disburses approved funds DIRECTLY to beneficiary.

    payload = {
        "RecipientName": "Beneficiary",
        "RecipientMsisdn": beneficiary_phone,

        "CallbackUrl": "https://adansi.app/api/withdrawals/callback",

    }

    response = requests.post(
        f"{HUBTEL_BASE_URL}/merchantaccount/merchants/{HUBTEL_CLIENT_ID}/send/mobilemoney",
        json=payload,
        auth=(HUBTEL_CLIENT_ID, HUBTEL_CLIENT_SECRET)
    )

    return {
        "reference": reference,
        "status": response.json().get("Status"),
        "transaction_id": response.json().get("TransactionId")
    }
```
