## 0. CORE PRINCIPLE (Settled)

**Adansi is a group treasury and social credit platform.** It is NOT a personal savings app. It is NOT a bank replacement. It is the financial infrastructure for Ghana's collective economy.

**What that means:**
- Every user must belong to at least one group to get value.
- Individual "personal wallets" may exist technically as a single-member group, but they are NEVER marketed, never shown on landing pages, and never pitched as a feature.
- The credit score is built from **group contribution behavior**, not personal deposits.

### 2.1 Platform Roles (Global)

| Role | Who | Permissions |
|------|-----|-------------|
| `user` | Regular member | Create/join groups, contribute, vote on withdrawals, view own dashboard |
| `agent` | MoMo agent | Access agent verification portal (future mock), verify withdrawals |
| `admin` | MTN/Platform staff | View admin dashboard, analytics, agent network stats |
| `super_admin` | Lead platform admin | Everything + user management |

**Default on signup:** `role = 'user'`

### 2.2 Per-Group Roles (Local to Group)

Stored in `group_members` table:

| Role | Who Can Assign | Powers |
|------|---------------|--------|
| `creator` | Auto-assigned on group creation | Cannot be removed. Can delete group. Can change group settings. |
| `treasurer` | Creator or 75% member vote | Can request withdrawals. Can receive disbursed funds. |
| `admin` | Creator | Can approve/reject join requests. Can remove members. Can change group settings. |
| `member` | Auto-assigned on join | Can contribute. Can vote on withdrawals (if rule requires). Can view group history. |

**Important:** A user can be `treasurer` in Group A and just `member` in Group B. These are per-group, not global.

### 3.2 Group Join Approval Workflow

**Current flaw:** Anyone with the code joins instantly.
**Fix:** Join requests must be approved by a group admin.

**Flow:**
```
User enters join code → Sees group preview → Taps "Request to Join"
→ Notification sent to group admin(s)
→ Admin sees: "Amina Owusu (+23324...) wants to join 'Funeral Fund'"
→ Admin taps "Approve" or "Reject"
→ If approved: user becomes 'member', receives confirmation
→ If rejected: user sees "Your request was declined"
```

**Database:**
```sql
CREATE TABLE IF NOT EXISTS join_requests (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  group_id UUID REFERENCES groups(id) ON DELETE CASCADE,
  user_id UUID REFERENCES users(id) ON DELETE CASCADE,
  status VARCHAR(20) DEFAULT 'pending' CHECK (status IN ('pending', 'approved', 'rejected')),
  requested_at TIMESTAMP DEFAULT NOW(),
  responded_at TIMESTAMP,
  responded_by UUID REFERENCES users(id)
);
```

**API:**
```http

→ Creates join_request record, notifies admins

POST /groups/:id/join-request/:requestId/respond
```

## 4. WITHDRAWAL ALGORITHM (OPTION C — NO MANDATORY AGENT VERIFICATION)

### 4.1 Core Rule

**Agent verification is REMOVED from the MVP.** Withdrawals are approved purely by digital treasury signatories.

**For Demo Day pitch:** "For large withdrawals, 2 of 3 treasurers must approve. This replaces the need for agent verification in the MVP. In Phase 2, we will integrate optional agent biometric verification via MTN's existing agent network for users who want extra security."

### 4.2 Withdrawal Processing Algorithm

```python
# Backend: withdrawals.py

from typing import List, Dict
from enum import Enum

class ApprovalRule(str, Enum):
    ANY_1_TREASURER = "any_1_treasurer"
    TWO_OF_THREE = "two_of_three_treasurers"
    MAJORITY_MEMBERS = "majority_members"
    UNANIMOUS_MEMBERS = "unanimous_members"

def process_withdrawal_request(group_id: str, requester_id: str, amount: float, reason: str, db) -> Dict:
    """
    Step 1: Validate request
    Step 2: Check auto-approve limit
    Step 3: Route to correct approval workflow
    """
    group = db.get_group(group_id)
    requester = db.get_member(group_id, requester_id)

    # Validation
    if requester["role"] not in ["treasurer", "creator"]:
        return {"error": "Only treasurers can request withdrawals"}

    if amount > group["balance"]:
        return {"error": "Insufficient group balance"}

    # Auto-approve check
    if amount <= group["auto_approve_limit"]:
        disburse_funds(group_id, requester_id, amount)
        return {
            "status": "disbursed",
            "withdrawal_id": generate_id(),
            "amount": amount,
            "method": "auto_approved"
        }

    # Create withdrawal request
    withdrawal = db.create_withdrawal({
        "group_id": group_id,
        "requester_id": requester_id,
        "amount": amount,
        "reason": reason,
        "status": "pending_approval",
        "required_approvals": calculate_required_approvals(group),
        "approvals_received": 0,
        "created_at": now(),
        "expires_at": now() + hours(group["approval_timeout_hours"])
    })

    notify_approvers(group, withdrawal)

    return {
        "status": "pending_approval",
        "withdrawal_id": withdrawal["id"],
        "required_approvals": withdrawal["required_approvals"],
        "timeout_hours": group["approval_timeout_hours"]
    }

def calculate_required_approvals(group: Dict) -> Dict:
    """
    Returns WHO needs to approve and HOW MANY.
    """
    rule = group["approval_rule"]
    treasurers = db.get_treasurers(group["id"])
    members = db.get_members(group["id"])

    if rule == ApprovalRule.ANY_1_TREASURER:
        return {"type": "treasurers", "count": 1, "pool_size": len(treasurers)}

    elif rule == ApprovalRule.TWO_OF_THREE:
        return {"type": "treasurers", "count": 2, "pool_size": min(3, len(treasurers))}

    elif rule == ApprovalRule.MAJORITY_MEMBERS:
        required = max(2, int(len(members) * 0.51))
        return {"type": "members", "count": required, "pool_size": len(members)}

    elif rule == ApprovalRule.UNANIMOUS_MEMBERS:
        return {"type": "members", "count": len(members), "pool_size": len(members)}

    return {"type": "treasurers", "count": 1, "pool_size": len(treasurers)}

def approve_withdrawal(withdrawal_id: str, approver_id: str, db) -> Dict:
    """
    Step 1: Validate approver is authorized
    Step 2: Record approval
    Step 3: Check if threshold met
    Step 4: If met, disburse
    """
    withdrawal = db.get_withdrawal(withdrawal_id)
    group = db.get_group(withdrawal["group_id"])
    approver = db.get_member(group["id"], approver_id)

    # Check expiry
    if now() > withdrawal["expires_at"]:
        db.update_withdrawal(withdrawal_id, {"status": "expired"})
        return {"error": "Withdrawal request has expired"}

    # Check if already approved
    if db.has_approved(withdrawal_id, approver_id):
        return {"error": "You have already approved this withdrawal"}

    # Validate approver based on rule
    req = withdrawal["required_approvals"]

    if req["type"] == "treasurers":
        if approver["role"] not in ["treasurer", "creator"]:
            return {"error": "Only treasurers can approve this withdrawal"}

    # Record approval
    db.record_approval(withdrawal_id, approver_id)
    current_count = db.get_approval_count(withdrawal_id)

    # Check threshold
    if current_count >= req["count"]:
        db.update_withdrawal(withdrawal_id, {
            "status": "approved",
            "approved_at": now()
        })
        disburse_funds(group["id"], withdrawal["requester_id"], withdrawal["amount"])
        notify_members(group["id"], f"Withdrawal of GHS {withdrawal['amount']} approved and disbursed")
        return {"status": "disbursed", "withdrawal_id": withdrawal_id}

    return {
        "status": "pending_approval",
        "approvals_received": current_count,
        "approvals_required": req["count"]
    }

def handle_expired_withdrawals(db):
    """
    Run this via cron job every hour.
    Non-voters are treated as ABSTAIN (not reject).
    """
    expired = db.query("""
        SELECT * FROM withdrawals 
        WHERE status = 'pending_approval' 
        AND expires_at < NOW()
    """)

    for w in expired:
        db.update_withdrawal(w["id"], {"status": "expired"})
        notify_members(w["group_id"], 
            f"Withdrawal request of GHS {w['amount']} expired due to insufficient approvals")
```

## 6. CREDIT SCORING

### 6.1 Algorithm

Credit score (0-850) built from group contribution behavior only:

| Factor | Weight | What It Measures |
|--------|--------|------------------|
| Consistency | 35% | On-time contributions (did you pay every week?) |
| Volume | 25% | Total amount contributed across all groups |
| Diversity | 15% | Number of different groups/types contributed to |
| Tenure | 10% | How long you've been contributing |
| Standing | 10% | Group standing (are you a treasurer? admin?) |
| Behavior | 5% | Approval participation, no fraud flags |

```python
def calculate_credit_score(user_id, db) -> int:
    contributions = db.get_user_contributions(user_id)
    groups = db.get_user_groups(user_id)

    consistency = calculate_on_time_rate(contributions) * 0.35
    volume = min(1.0, total_volume / 10_000) * 0.25  # Cap at GHS 10k
    diversity = min(1.0, len(groups) / 5) * 0.15
    tenure = min(1.0, days_since_first_contribution / 180) * 0.10
    standing = calculate_standing_score(groups) * 0.10
    behavior = calculate_behavior_score(user_id) * 0.05

    score = (consistency + volume + diversity + tenure + standing + behavior) * 850
    return min(850, max(0, int(score)))
```

### 9.2 Future Concept Spec (For Pitch Deck Only)

**If judges ask about agent verification, describe this future flow:**

```
1. Treasurer requests large withdrawal (e.g., GHS 8,000)
2. Digital approval passes (2 of 3 treasurers approve)
3. System generates WITHDRAWAL VERIFICATION CODE: AD-7X9K2M
4. One-time PIN sent to treasurer's SMS
5. Treasurer walks into ANY MoMo agent
6. Agent enters code into MTN Agent Portal (or dials USSD: *422*9*AD-7X9K2M#)
7. Agent sees: Group name, amount, treasurer photo from Ghana Card DB
8. Agent checks Ghana Card photo against person + SMS OTP
9. Agent confirms → funds release
```

**Why this works without admin assignment:**
- Security comes from the CODE + GHANA CARD + SMS OTP triple-check
- Any agent can verify because the agent must be logged into the official MTN Agent Portal
- Fraud is traceable to the specific agent ID and location
- No bottleneck, no waiting for a platform admin to wake up

### 9.3 Pitch Script for Judges

> "For the MVP, we use multi-signature treasury approval — 2 of 3 treasurers digitally approve withdrawals. This eliminates the need for agent verification in the core product. In Phase 2, for users who want extra security or for amounts above GHS 10,000, we will integrate optional agent verification into MTN's existing agent USSD menu. The agent becomes a human KYC terminal, not a gatekeeper."

```sql
-- Users
CREATE TABLE users (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),

);

-- Groups
CREATE TABLE groups (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  name VARCHAR(255) NOT NULL,
  type VARCHAR(50) CHECK (type IN ('funeral', 'wedding', 'health', 'savings', 'investment', 'business', 'personal')),
  description TEXT,
  target_amount DECIMAL(12,2),
  contribution_amount DECIMAL(12,2),
  frequency VARCHAR(20) CHECK (frequency IN ('daily', 'weekly', 'monthly', 'one_time')),
  join_code VARCHAR(10) UNIQUE,
  approval_rule VARCHAR(50) DEFAULT 'any_1_treasurer',
  auto_approve_limit DECIMAL(12,2) DEFAULT 0,
  approval_timeout_hours INT DEFAULT 24,
  join_type VARCHAR(20) DEFAULT 'approval_required',
  balance DECIMAL(12,2) DEFAULT 0,
  created_by UUID REFERENCES users(id),
  created_at TIMESTAMP DEFAULT NOW()
);

-- Group Members
CREATE TABLE group_members (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  group_id UUID REFERENCES groups(id) ON DELETE CASCADE,
  user_id UUID REFERENCES users(id) ON DELETE CASCADE,
  role VARCHAR(20) DEFAULT 'member' CHECK (role IN ('creator', 'admin', 'treasurer', 'member')),
  joined_at TIMESTAMP DEFAULT NOW(),
  UNIQUE(group_id, user_id)
);

-- Contributions
CREATE TABLE contributions (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  group_id UUID REFERENCES groups(id) ON DELETE CASCADE,
  user_id UUID REFERENCES users(id),
  amount DECIMAL(12,2) NOT NULL,
  method VARCHAR(20) CHECK (method IN ('momo', 'card', 'ussd')),

  hubtel_transaction_id VARCHAR(100),
  created_at TIMESTAMP DEFAULT NOW()
);

-- Withdrawals
CREATE TABLE withdrawals (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  group_id UUID REFERENCES groups(id) ON DELETE CASCADE,
  requester_id UUID REFERENCES users(id),
  amount DECIMAL(12,2) NOT NULL,
  reason TEXT,
  status VARCHAR(20) DEFAULT 'pending_approval' CHECK (status IN ('pending_approval', 'approved', 'rejected', 'expired', 'disbursed')),

  created_at TIMESTAMP DEFAULT NOW(),
  expires_at TIMESTAMP,
  approved_at TIMESTAMP,
  disbursed_at TIMESTAMP
);

-- Withdrawal Approvals
CREATE TABLE withdrawal_approvals (

  UNIQUE(withdrawal_id, approver_id)
);

-- Join Requests
CREATE TABLE join_requests (
```

```http
GET /groups/:id/withdrawals
→ List withdrawals for group
```

```http
→ Returns current score + breakdown

Body: { amount, purpose, group_vouch_ids? }
→ Creates loan application (mock for hackathon)

GET /credit/loans
→ Loan history
```
