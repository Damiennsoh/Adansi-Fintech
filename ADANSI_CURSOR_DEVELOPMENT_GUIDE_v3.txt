## 0. CORE PRINCIPLE (Settled & Frozen)

**Adansi is a group treasury, social credit, and direct-disbursement platform.**

**What that means:**
- Every user must belong to at least one group to get value.
- Individual "personal wallets" exist technically as a single-member group, but are NEVER marketed, never shown on landing pages, and never pitched.
- The credit score is built from **group contribution behavior**, not personal deposits.
- **Money NEVER touches the treasurer's personal wallet.** Approved withdrawals disburse DIRECTLY to the beneficiary's MoMo or bank account.
- **Cross-network by default.** Contributions and disbursements work across MTN, Telecel, and AirtelTigo.

## 2. USER MODEL & ROLES

### 2.1 Platform Roles (Global)

| Role | Who | Permissions |
|------|-----|-------------|
| `user` | Regular member | Create/join groups, contribute, vote on withdrawals, view own dashboard |
| `agent` | MoMo agent | Access agent verification portal (future mock), verify withdrawals |
| `admin` | MTN/Platform staff | View admin dashboard, analytics, agent network stats |
| `super_admin` | Lead platform admin | Everything + user management |

**Default on signup:** `role = 'user'`

### 2.2 Per-Group Roles (Local to Group)

Stored in `group_members` table:

| Role | Who Can Assign | Powers |
|------|---------------|--------|
| `creator` | Auto-assigned on group creation | Cannot be removed. Can delete group. Can change group settings. |
| `treasurer` | Creator or 75% member vote | Can REQUEST withdrawals. Can nominate beneficiaries. Cannot receive funds personally. |
| `admin` | Creator | Can approve/reject join requests. Can remove members. Can change group settings. |
| `member` | Auto-assigned on join | Can contribute. Can vote on withdrawals (if rule requires). Can view group history. |

**CRITICAL:** Treasurers are **requesters and nominators**, not **recipients**. The money goes to the beneficiary they nominate, not to their personal wallet.

## 4. WITHDRAWAL ALGORITHM WITH DIRECT BENEFICIARY DISBURSEMENT

### 4.1 Core Rule

**Money NEVER enters the treasurer's personal wallet.** After digital approval, funds disburse DIRECTLY to the nominated beneficiary's MoMo or bank account via Hubtel.

**For Demo Day pitch:** "When 2 of 3 treasurers approve a funeral withdrawal, the GHS 1,500 goes straight to the coffin maker's MoMo. The treasurer never touches the cash. This eliminates the #1 fear in group finance: the treasurer running away with the money."

### 4.2 Withdrawal Request Flow

```
Treasurer opens Group Detail → Taps "Request Withdrawal"
→ Enters:
   - amount (e.g., GHS 1,500)
   - reason (e.g., "Coffin deposit & hearse booking")
   - beneficiary_name (e.g., "Nsawam Coffin Works")
   - beneficiary_phone (e.g., "+23324...")
   - beneficiary_network (dropdown: MTN / Telecel / AirtelTigo)
   - disbursement_method (momo / bank_transfer)
   - beneficiary_bank_account (only if bank_transfer)
→ System shows preview: "GHS 1,500 will be sent to Nsawam Coffin Works (+23324...) after approval"
→ Treasurer confirms → Withdrawal request created with status 'pending_approval'
→ Notifications fire to approvers (other treasurers or members, depending on rule)
```

### 4.3 Approval & Disbursement Flow

```
Approver opens notification → Sees:
   - Requester: Kofi Mensah (Treasurer)
   - Amount: GHS 1,500
   - Reason: Coffin deposit & hearse booking
   - Beneficiary: Nsawam Coffin Works (+23324...)
   - Signatures: 1 of 2 Required
→ Approver taps "Approve & Sign Digitally"
→ System checks if threshold met
→ IF threshold met:
   - Status → 'approved'
   - Hubtel API call: disburse funds to beneficiary_phone
   - Status → 'disbursed'
   - Receipt generated: "GHS 1,500 sent to Nsawam Coffin Works"
   - Group balance reduced by GHS 1,500
   - Notifications sent to all members: "Withdrawal of GHS 1,500 to Nsawam Coffin Works approved and disbursed"
→ IF threshold NOT met:
   - Status remains 'pending_approval'
   - Progress bar updates: "2 of 2 Required"
```

### 4.4 Rotating Savings (Susu) Disbursement

For rotating savings groups, the system maintains a queue:

```sql
-- rotation_queue stored as JSONB in groups table
-- Example: [{"user_id": "uuid-1", "position": 1}, {"user_id": "uuid-2", "position": 2}, ...]
```

**Flow:**
```
At end of each cycle (weekly/monthly):
→ System auto-identifies next beneficiary from rotation_queue
→ Treasurer taps "Disburse to Next Beneficiary" (pre-filled with next person's details)
→ Approval rule applied (e.g., 2 of 3 treasurers)
→ On approval: funds go DIRECTLY to that member's MoMo
→ Rotation queue advances: position 1 moves to end of queue
→ All members see: "Yaw Addo received GHS 2,000 this cycle. Next: Amina Owusu"
```

### 4.5 Withdrawal Processing Algorithm

```python
# Backend: withdrawals.py

from typing import List, Dict
from enum import Enum

class ApprovalRule(str, Enum):
    ANY_1_TREASURER = "any_1_treasurer"
    TWO_OF_THREE = "two_of_three_treasurers"
    MAJORITY_MEMBERS = "majority_members"
    UNANIMOUS_MEMBERS = "unanimous_members"

class DisbursementMethod(str, Enum):
    MOMO = "momo"
    BANK_TRANSFER = "bank_transfer"

class Network(str, Enum):
    MTN = "mtn"
    TELECEL = "telecel"
    AIRTELTIGO = "airteltigo"

def process_withdrawal_request(
    group_id: str,
    requester_id: str,
    amount: float,
    reason: str,
    beneficiary_name: str,
    beneficiary_phone: str,
    beneficiary_network: Network,
    disbursement_method: DisbursementMethod,
    beneficiary_bank_account: str = None,
    db
) -> Dict:
    """
    Step 1: Validate request
    Step 2: Check auto-approve limit
    Step 3: Route to correct approval workflow
    """
    group = db.get_group(group_id)
    requester = db.get_member(group_id, requester_id)

    # Validation
    if requester["role"] not in ["treasurer", "creator"]:
        return {"error": "Only treasurers can request withdrawals"}

    if amount > group["balance"]:
        return {"error": "Insufficient group balance"}

    # Validate beneficiary phone format
    if not validate_ghana_phone(beneficiary_phone):
        return {"error": "Invalid beneficiary phone number"}

    # Auto-approve check
    if amount <= group["auto_approve_limit"]:
        result = disburse_funds(
            group_id=group_id,
            amount=amount,
            beneficiary_phone=beneficiary_phone,
            beneficiary_network=beneficiary_network.value,
            disbursement_method=disbursement_method.value,
            beneficiary_bank_account=beneficiary_bank_account,
            reason=reason
        )
        return {
            "status": "disbursed",
            "withdrawal_id": generate_id(),
            "amount": amount,
            "method": "auto_approved",
            "beneficiary": beneficiary_name,
            "transaction_ref": result["reference"]
        }

    # Create withdrawal request
    withdrawal = db.create_withdrawal({
        "group_id": group_id,
        "requester_id": requester_id,
        "amount": amount,
        "reason": reason,
        "beneficiary_name": beneficiary_name,
        "beneficiary_phone": beneficiary_phone,
        "beneficiary_network": beneficiary_network.value,
        "disbursement_method": disbursement_method.value,
        "beneficiary_bank_account": beneficiary_bank_account,
        "status": "pending_approval",
        "required_approvals": calculate_required_approvals(group),
        "approvals_received": 0,
        "created_at": now(),
        "expires_at": now() + hours(group["approval_timeout_hours"])
    })

    notify_approvers(group, withdrawal)

    return {
        "status": "pending_approval",
        "withdrawal_id": withdrawal["id"],
        "required_approvals": withdrawal["required_approvals"],
        "timeout_hours": group["approval_timeout_hours"],
        "beneficiary": beneficiary_name
    }

def calculate_required_approvals(group: Dict) -> Dict:
    """
    Returns WHO needs to approve and HOW MANY.
    """
    rule = group["approval_rule"]
    treasurers = db.get_treasurers(group["id"])
    members = db.get_members(group["id"])

    if rule == ApprovalRule.ANY_1_TREASURER:
        return {"type": "treasurers", "count": 1, "pool_size": len(treasurers)}

    elif rule == ApprovalRule.TWO_OF_THREE:
        return {"type": "treasurers", "count": 2, "pool_size": min(3, len(treasurers))}

    elif rule == ApprovalRule.MAJORITY_MEMBERS:
        required = max(2, int(len(members) * 0.51))
        return {"type": "members", "count": required, "pool_size": len(members)}

    elif rule == ApprovalRule.UNANIMOUS_MEMBERS:
        return {"type": "members", "count": len(members), "pool_size": len(members)}

    return {"type": "treasurers", "count": 1, "pool_size": len(treasurers)}

def approve_withdrawal(withdrawal_id: str, approver_id: str, db) -> Dict:
    """
    Step 1: Validate approver is authorized
    Step 2: Record approval
    Step 3: Check if threshold met
    Step 4: If met, disburse DIRECTLY to beneficiary (NOT to requester)
    """
    withdrawal = db.get_withdrawal(withdrawal_id)
    group = db.get_group(withdrawal["group_id"])
    approver = db.get_member(group["id"], approver_id)

    # Check expiry
    if now() > withdrawal["expires_at"]:
        db.update_withdrawal(withdrawal_id, {"status": "expired"})
        return {"error": "Withdrawal request has expired"}

    # Check if already approved
    if db.has_approved(withdrawal_id, approver_id):
        return {"error": "You have already approved this withdrawal"}

    # Validate approver based on rule
    req = withdrawal["required_approvals"]

    if req["type"] == "treasurers":
        if approver["role"] not in ["treasurer", "creator"]:
            return {"error": "Only treasurers can approve this withdrawal"}

    # Record approval
    db.record_approval(withdrawal_id, approver_id)
    current_count = db.get_approval_count(withdrawal_id)

    # Check threshold
    if current_count >= req["count"]:
        # DISBURSE DIRECTLY TO BENEFICIARY — NOT TO REQUESTER
        result = disburse_funds(
            group_id=group["id"],
            amount=withdrawal["amount"],
            beneficiary_phone=withdrawal["beneficiary_phone"],
            beneficiary_network=withdrawal["beneficiary_network"],
            disbursement_method=withdrawal["disbursement_method"],
            beneficiary_bank_account=withdrawal.get("beneficiary_bank_account"),
            reason=withdrawal["reason"]
        )

        db.update_withdrawal(withdrawal_id, {
            "status": "disbursed",
            "approved_at": now(),
            "disbursed_at": now(),
            "transaction_ref": result["reference"]
        })

        notify_members(group["id"], 
            f"GHS {withdrawal['amount']} disbursed to {withdrawal['beneficiary_name']} ({withdrawal['beneficiary_phone']})")

        return {
            "status": "disbursed",
            "withdrawal_id": withdrawal_id,
            "beneficiary": withdrawal["beneficiary_name"],
            "transaction_ref": result["reference"]
        }

    return {
        "status": "pending_approval",
        "approvals_received": current_count,
        "approvals_required": req["count"]
    }

def disburse_funds(
    group_id: str,
    amount: float,
    beneficiary_phone: str,
    beneficiary_network: str,
    disbursement_method: str,
    beneficiary_bank_account: str = None,
    reason: str = ""
) -> Dict:
    """
    Calls Hubtel API to disburse funds DIRECTLY to beneficiary.
    NEVER to the treasurer's personal wallet.
    """
    if disbursement_method == "momo":
        # Hubtel MoMo disbursement API
        response = hubtel_client.disburse_momo(
            recipient=beneficiary_phone,
            network=beneficiary_network,  # 'mtn', 'telecel', 'airteltigo'
            amount=amount,
            description=reason
        )
    elif disbursement_method == "bank_transfer":
        # Hubtel bank transfer API
        response = hubtel_client.disburse_bank(
            account_number=beneficiary_bank_account,
            amount=amount,
            description=reason
        )

    # Deduct from group balance
    db.deduct_group_balance(group_id, amount)

    return {
        "reference": response["transaction_id"],
        "status": "success"
    }

def handle_expired_withdrawals(db):
    """
    Run this via cron job every hour.
    Non-voters are treated as ABSTAIN (not reject).
    """
    expired = db.query("""
        SELECT * FROM withdrawals 
        WHERE status = 'pending_approval' 
        AND expires_at < NOW()
    """)

    for w in expired:
        db.update_withdrawal(w["id"], {"status": "expired"})
        notify_members(w["group_id"], 
            f"Withdrawal request of GHS {w['amount']} to {w['beneficiary_name']} expired due to insufficient approvals")
```

## 5. CROSS-NETWORK SUPPORT

### 5.1 Hubtel Multi-Network Capability

Hubtel's MoMo API supports all three Ghanaian mobile money networks:
- **MTN MoMo** (network code: "mtn")
- **Telecel Cash** (network code: "telecel")
- **AirtelTigo Money** (network code: "airteltigo")

### 5.2 Contribution Flow (Cross-Network)

```
User opens Contribute Page
→ Selects group
→ Enters amount
→ SELECTS NETWORK (dropdown: MTN / Telecel / AirtelTigo)
→ System detects network from phone prefix as default, but user can override
→ Taps "Contribute"
→ Hubtel API initiates payment request on selected network
→ User receives MoMo prompt on their phone (regardless of network)
→ User confirms with PIN
→ Hubtel callback confirms payment
→ Contribution recorded in Adansi DB
```

### 5.3 Disbursement Flow (Cross-Network)

```
Treasurer requests withdrawal
→ Enters beneficiary details
→ SELECTS BENEFICIARY NETWORK (dropdown: MTN / Telecel / AirtelTigo)
→ System auto-detects from phone prefix but allows override
→ On approval: Hubtel disburses to that network
→ Beneficiary receives MoMo alert from their own network
```

### 5.5 Backend Network Validation

```python
def validate_ghana_phone(phone: str) -> bool:
    """Validate Ghana phone number format."""
    import re
    pattern = r'^\+233(20|24|50|54|55|26|56|57)\d{7}$'
    return re.match(pattern, phone) is not None

def detect_network(phone: str) -> str:
    """Auto-detect network from phone prefix."""
    prefix = phone[4:6]  # +23324 → 24
    mtn_prefixes = ['20', '24', '54', '55', '59']
    telecel_prefixes = ['50']
    airteltigo_prefixes = ['26', '56', '57', '27']

    if prefix in mtn_prefixes:
        return 'mtn'
    elif prefix in telecel_prefixes:
        return 'telecel'
    elif prefix in airteltigo_prefixes:
        return 'airteltigo'
    return 'mtn'  # Default
```

## 6. CONTRIBUTION HISTORY & AUDIT TRANSPARENCY

### 6.1 Why This Is Necessary (Not Overkill)

1. **Feeds the credit score algorithm.** Without historical data, the score is fiction.
2. **Member accountability.** Damien Nsoh sees he was 2 days late. Social pressure improves behavior.
3. **Dispute resolution.** "I contributed GHS 500 on January 15" — the ledger proves it.
4. **Lender requirement.** When Rural Bank X pulls a credit report, they want 12+ months of data.
5. **Group trust.** Everyone sees who paid, who didn't, and when.

### 6.2 Database Schema

```sql
-- Contribution schedules (expected payments)
CREATE TABLE contribution_schedules (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  group_id UUID REFERENCES groups(id) ON DELETE CASCADE,
  user_id UUID REFERENCES users(id),
  expected_date DATE NOT NULL,
  expected_amount DECIMAL(12,2) NOT NULL,
  status VARCHAR(20) DEFAULT 'pending' CHECK (status IN ('pending', 'paid', 'late', 'missed')),
  paid_at TIMESTAMP,
  contribution_id UUID REFERENCES contributions(id), -- Link to actual payment
  created_at TIMESTAMP DEFAULT NOW()
);

-- Monthly / periodic summaries (for fast querying)
CREATE TABLE group_monthly_summaries (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  group_id UUID REFERENCES groups(id) ON DELETE CASCADE,
  year INT NOT NULL,
  month INT NOT NULL,
  total_contributions DECIMAL(12,2) DEFAULT 0,
  total_withdrawals DECIMAL(12,2) DEFAULT 0,
  member_count INT DEFAULT 0,
  contribution_count INT DEFAULT 0,
  UNIQUE(group_id, year, month)
);

-- Individual contribution history view (materialized or computed)
-- This is a VIEW, not a table:
CREATE VIEW user_contribution_history AS
SELECT 
  c.user_id,
  c.group_id,
  g.name as group_name,
  c.amount,
  c.status,
  c.method,
  c.created_at,
  cs.status as schedule_status, -- 'on_time', 'late', 'missed'
  CASE 
    WHEN cs.paid_at <= cs.expected_date THEN 'on_time'
    WHEN cs.paid_at > cs.expected_date THEN 'late'
    ELSE 'missed'
  END as timeliness
FROM contributions c
LEFT JOIN contribution_schedules cs ON cs.contribution_id = c.id
LEFT JOIN groups g ON g.id = c.group_id;
```

## 7. CREDIT SCORING & PARTNER LENDERS

### 7.1 Social Credit Score Algorithm

```python
def calculate_credit_score(user_id, db) -> int:
    """
    Score (0-850) built purely from group contribution behavior.
    """
    contributions = db.get_user_contributions(user_id)
    groups = db.get_user_groups(user_id)
    schedules = db.get_user_schedules(user_id)
    approvals = db.get_user_approval_participation(user_id)

    # Consistency (35%): On-time payment rate
    total_scheduled = len(schedules)
    on_time = sum(1 for s in schedules if s.timeliness == 'on_time')
    consistency = (on_time / total_scheduled if total_scheduled > 0 else 0) * 0.35

    # Volume (25%): Total amount contributed, capped at GHS 10k
    total_volume = sum(c.amount for c in contributions)
    volume = min(1.0, total_volume / 10_000) * 0.25

    # Diversity (15%): Number of different groups contributed to, capped at 5
    diversity = min(1.0, len(groups) / 5) * 0.15

    # Tenure (10%): Days since first contribution, capped at 180 days
    first_contribution = min(c.created_at for c in contributions) if contributions else now()
    days_active = (now() - first_contribution).days
    tenure = min(1.0, days_active / 180) * 0.10

    # Standing (10%): Group roles
    role_score = 0
    for g in groups:
        if g.role == 'creator': role_score += 1.0
        elif g.role == 'treasurer': role_score += 0.8
        elif g.role == 'admin': role_score += 0.6
        else: role_score += 0.3
    standing = min(1.0, role_score / len(groups) if groups else 0) * 0.10

    # Behavior (5%): Approval participation, no fraud flags
    total_approval_requests = len(approvals)
    approval_responses = sum(1 for a in approvals if a.responded)
    behavior = (approval_responses / total_approval_requests if total_approval_requests > 0 else 0.5) * 0.05

    score = (consistency + volume + diversity + tenure + standing + behavior) * 850
    return min(850, max(0, int(score)))
```

### 7.4 How External Lenders Would Integrate (Post-Hackathon Spec)

**Model A: Adansi as Credit Bureau (Data Provider)**
```
Rural Bank X receives loan application from Adansi user
→ Bank requests credit report via Adansi API
→ User gets notification: "Rural Bank X wants to view your credit score. Approve?"
→ User taps "Approve"
→ Adansi sends verified credit report (read-only, no raw data):
   - Score: 720 (Gold Tier)
   - Contribution history: 18 months, 98% on-time
   - Groups: 3 active, total volume GHS 8,500
   - Standing: Treasurer in 1 group, member in 2
   - Loan history: 2 previous loans, 100% repayment
→ Rural Bank X makes independent decision
→ Adansi charges Rural Bank X GHS 5-10 per credit pull
```

**Model B: Adansi as Loan Marketplace (Originator)**
```
Adansi partners with licensed MFIs and rural banks
→ Lenders post loan products on Adansi platform
→ Groups/users with qualifying scores see offers
→ Application pre-filled with verified group data
→ Lender reviews, approves, disburses
→ Adansi takes 2-3% origination fee from lender (not borrower)
```

**Security measures:**
- OAuth-style user consent required for every credit pull
- Lenders must be KYC-verified by Adansi admin (license check)
- Credit reports are read-only snapshots, not live data access
- Default reporting: lenders report back defaults, which drop user's score
- Data encryption: all credit data encrypted at rest and in transit

  c.user_id,
  c.group_id,
  g.name as group_name,
  c.amount,
  c.status,
  c.method,
  c.network,
  c.created_at,

    WHEN cs.paid_at <= cs.expected_date THEN 'on_time'
    WHEN cs.paid_at > cs.expected_date THEN 'late'
    ELSE 'missed'
